## ⚠️ Chrome 调试端口踩坑记录（重要！）

### 坑 1：Chrome Canary 需要 `--user-data-dir`
```
错误日志：DevTools remote debugging requires a non-default data directory.
Specify this using --user-data-dir.
```
**原因**：Chrome Canary 的默认 User Data 目录被认为是 "default"，不允许远程调试。
**解决**：必须显式指定 `--user-data-dir`，即使指向同一个目录。

### 坑 2：路径有空格导致参数截断
**路径**：`C:\Users\94556\AppData\Local\Google\Chrome SxS\User Data`
**问题**：`Chrome SxS` 和 `User Data` 都有空格，传参时可能被截断。
**解决**：用短路径 `C:\Users\94556\AppData\Local\Google\CHROME~1\USERDA~1`

### 坑 3：`-RedirectStandardError` 才能让端口生效
**问题**：PowerShell 的 `Start-Process` 不加 `-RedirectStandardError`，Chrome 的 stderr 输出被阻塞，导致端口没有打开。
**解决**：加上 `--enable-logging=stderr` 参数，或用 `-RedirectStandardError` 重定向。

### 坑 4：同一 User Data 只能一个实例！！！（最重要的坑！）
**问题**：主人手动打开的 Chrome 占用了 User Data 目录，灵儿再启动新实例无法使用同一个数据。
**后果**：灵儿打开的 Chrome 没有主人的登录状态。
**正确做法**：让主人正常使用的 Chrome 就带调试参数启动，不要灵儿单独启动新实例！

### 坑 5：强制关闭 Chrome 可能丢失 session
**问题**：`Stop-Process -Force` 不会让 Chrome 正常保存 session cookie。
**教训**：不要随意强制关闭主人的 Chrome！
